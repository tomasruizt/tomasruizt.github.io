Benchmark logs and metric sources

Each concurrency links to the original AIPerf exports used by the report. Values in console logs are rounded; some metrics are not printed.

  • Output tok/s: Metrics JSON → output_token_throughput.avg.
  • ITL p99: Metrics JSON → inter_chunk_latency.p99 (ms). This is the gap between streamed content chunks, which can contain multiple tokens. It is not printed in the benchmark console table.
  • TTFT p99: Metrics JSON → time_to_first_token.p99 (ms).
  • TPOT p90: Metrics JSON → inter_token_latency.p90 (ms). The console calls this “Inter Token Latency”; the report labels it TPOT.
  • Pareto plot: x = 1000 / inter_token_latency.p90; y = output_token_throughput.avg.
  • vLLM / PR 52297 AL: Server metrics JSON → 1 + sum(metrics["vllm:spec_decode_num_accepted_tokens"].series[*].stats.total) / sum(metrics["vllm:spec_decode_num_drafts"].series[*].stats.total).
  • SGLang AL: Server metrics JSON → sum(metrics["sglang:spec_accept_length"].series[*].stats.avg) (one series for these TP1 runs). Both AL values include the bonus token; the SGLang sampled gauge average has different weighting from the vLLM counter ratio. Summary JSON records AL and its method; baselines have no AL.
  • Cache capacity: Server log → vLLM GPU KV cache size or SGLang max_total_num_tokens. Divide by 131072 for 128K sequence equivalents. Config JSON → server_command records the configured request limit.

These exports allow checking the reported aggregates and AL arithmetic. Independently recomputing percentiles from individual requests would additionally require the per-request traces, which are not included in this report bundle.
